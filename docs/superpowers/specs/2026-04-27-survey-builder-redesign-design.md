# Редизайн конструктора опросов

## Контекст

Страница `Опросы` уже содержит конструктор, клиентскую аналитику, аналитику сотрудников и сводную аналитику. На этом этапе в работу входит только вкладка `Конструктор`.

Текущая реализация конструктора перегружена текстом, не выделяет активный опрос, не дает компактной структуры для сохраненных шаблонов и не держит единый визуальный ритм для карточек, полей и селектов.

Пользовательский запрос для этой итерации:

- переработать только конструктор;
- сохранить стиль приложения: те же цвета, тот же шрифт, те же базовые паттерны карточек и контролов;
- сделать карточки компактными;
- убрать лишний текст и оставить только основные заголовки;
- не допускать переноса служебного текста на карточках;
- унифицировать dropdown/select-паттерны.

## Цель

Собрать компактный и понятный конструктор опросов с двухзонной компоновкой:

- слева навигационный сайдбар по типу аудитории и шаблонам;
- справа вертикальная рабочая колонка карточек для настройки опроса и редактирования вопросов.

Экран должен быть удобен для длинных вопросов и длинных форм без перехода к двухколоночному редактору.

## Не входит в задачу

- редизайн вкладок аналитики клиентов;
- редизайн вкладок аналитики сотрудников;
- редизайн сводной аналитики;
- изменение API, структуры данных или серверных контрактов;
- изменение общей навигации верхнего уровня за пределами вкладки `Конструктор`.

## Принятое решение

Используется layout `сайдбар + единая вертикальная колонка карточек`.

Причины выбора:

- длинные вопросы и списки вариантов естественно помещаются в одну колонку;
- не появляется конкуренция между списком вопросов и отдельной областью редактирования;
- экран проще привести к компактному виду без лишних блоков и дублирования элементов;
- структура напрямую соответствует пользовательскому сценарию: выбрать опрос, открыть, пройтись сверху вниз по карточкам.

## Структура экрана

### Верхний уровень

Во вкладке `Конструктор` экран делится на две области:

1. левый сайдбар фиксированной или полуфиксированной ширины;
2. правая рабочая область на всю оставшуюся ширину.

Общая шапка страницы `Опросы` и верхние табы секций сохраняются.

### Левый сайдбар

Сайдбар состоит из трех блоков:

1. переключатель аудитории `Клиенты / Сотрудники`;
2. секция `Активный опрос`;
3. секция `Сохраненные опросы`.

#### Переключатель аудитории

- визуально оформлен как slider/segmented control;
- содержит два состояния: `Клиенты` и `Сотрудники`;
- переключает набор доступных шаблонов без смены общей структуры страницы.

#### Секция `Активный опрос`

- всегда показывает один текущий активный шаблон для выбранной аудитории, если он есть;
- карточка содержит название и компактную статусную строку;
- статусная строка может включать статус и короткий признак запуска;
- карточка визуально сильнее остальных: более заметная подложка или контрастная рамка в рамках текущего дизайн-языка.

#### Секция `Сохраненные опросы`

- содержит остальные шаблоны для выбранной аудитории;
- каждая карточка показывает название и компактную статусную строку;
- длинный текст в строках режется по `ellipsis`, без переноса;
- активное выбранное состояние отличается цветом рамки и фона, но не ломает визуальную систему страницы.

## Правая рабочая область

Правая часть состоит из вертикальной последовательности карточек.

### Карточка шапки опроса

Первая карточка содержит только основные поля:

- `Название опроса`;
- `Статус`;
- действия `Сохранить`, `Дублировать`, `Удалить`.

Требования:

- без длинных пояснений и вспомогательных абзацев;
- `Статус` оформляется через тот же dropdown-паттерн, который используется в приложении;
- кнопки компактные, одного размера и в одном визуальном ряду.

### Карточка `Запуск`

Вторая карточка - отдельный блок настроек запуска опроса.

На основной карточке отображаются:

- заголовок `Запуск`;
- краткое текущее состояние сценария, например `После обращения`, `Начало месяца`, `Своя дата: 15.05.2026`;
- кнопка `Настроить`.

Детальные параметры не раскрываются прямо в основном полотне по умолчанию. Они открываются в модальном окне.

#### Модальное окно настроек запуска

Модальное окно содержит сценарии запуска:

- `Начало месяца`;
- `После обращения`;
- `Конец обращения`;
- `Своя дата`;
- дополнительные параметры только если они уже поддерживаются данными и реально нужны.

Принцип:

- главный экран остается чистым и компактным;
- сложность сценариев запуска изолируется в одном месте;
- если настройки со временем вырастут, не придется перестраивать главный layout конструктора.

### Список карточек вопросов

Ниже карточки запуска располагается единый вертикальный список вопросов.

Каждый вопрос представлен карточкой, которая поддерживает два состояния:

- свернутое;
- раскрытое для редактирования.

#### Свернутое состояние

Карточка показывает:

- заголовок вопроса;
- тип вопроса;
- короткое превью содержимого;
- действия `Изменить` и `Удалить`.

Превью зависит от типа:

- `Шкала оценки`: `Шкала 1-10`;
- `Один выбор`: первые 1-2 варианта;
- `Множественный выбор`: первые 1-2 варианта и, при необходимости, `+ еще N`;
- `Комментарий`: `Текстовый ответ`.

Служебные строки не переносятся и режутся по `ellipsis`.

#### Раскрытое состояние

Карточка редактируется прямо на месте, внутри общего вертикального потока.

Общие поля карточки:

- текст вопроса;
- тип вопроса;
- контент в зависимости от типа.

Перехода в отдельную правую панель или второй столбец не используется.

## Типы вопросов

Поддерживаются только следующие типы:

- `Шкала оценки`;
- `Один выбор`;
- `Множественный выбор`;
- `Комментарий`.

Тип `employee_exclusion` или другие специальные типы в этом редизайне не считаются центральной частью интерфейса и не влияют на утвержденный визуальный сценарий. Если их нужно оставить технически, они должны быть встроены в общий паттерн без изменения основного дизайна.

### Шкала оценки

В раскрытом виде:

- отображается текст вопроса;
- тип `Шкала оценки`;
- визуальный ряд значений от `1` до `10`.

Для шкалы используется не стандартный `range`, а компактный горизонтальный ряд значений, допускающий скролл при узком экране.

Причины:

- пользователь сразу видит весь диапазон;
- интерфейс выглядит как часть конструктора, а не как системный input;
- проще выдержать единый стиль карточек.

### Один выбор

В раскрытом виде:

- список компактных строк вариантов;
- каждая строка содержит radio-маркер, текст варианта и удаление;
- внизу кнопка `Добавить вариант`.

### Множественный выбор

Строится по тому же паттерну, что и `Один выбор`, но вместо radio-маркера используется checkbox-маркер.

Требование:

- сохранить единый каркас карточки;
- различие между типами показывать через маркер выбора и подпись типа, а не через отдельный визуальный язык.

### Комментарий

Самая компактная карточка.

В раскрытом виде:

- текст вопроса;
- тип `Комментарий`;
- без дополнительных длинных подсказок и лишних вспомогательных блоков.

## Добавление вопроса

Внизу списка вопросов находится одна компактная, но заметная кнопка `Добавить вопрос`.

После добавления:

- создается новая карточка внизу списка;
- карточка сразу открывается в режиме редактирования.

## Правила компактности и визуальной консистентности

### Текст

- на карточках сохраняются только основные заголовки;
- пояснительные абзацы и служебные описания убираются;
- служебный текст, подписи типов, статусы, превью и короткие метки не переносятся;
- для длинных строк применяется `ellipsis`;
- перенос допускается только для основного текста вопроса и длинных редактируемых пользовательских значений.

### Контролы

Все dropdown, select, inputs и кнопки должны использовать один и тот же визуальный паттерн:

- одинаковая высота;
- одинаковые радиусы;
- одинаковая толщина рамки;
- одинаковые состояния hover/focus/disabled;
- те же цвета, что уже используются на странице `Опросы` и в остальном webapp.

### Карточки

- карточки компактные по высоте;
- расстояния между карточками умеренные и равномерные;
- заголовки короткие и контрастные;
- фоны и тени соответствуют существующему стилю приложения;
- активные и выбранные элементы выделяются мягко, без нового цветового языка.

## Адаптивность

### Desktop

- двухзонный layout остается основным;
- сайдбар слева, редактор справа.

### Tablet / mobile

- сайдбар уходит над рабочей областью;
- карточки продолжают идти одной колонкой;
- шкала `1-10` может скроллиться по горизонтали;
- кнопки действий могут уходить на следующую строку, но без нарушения общего паттерна компактности.

## Переиспользование существующих паттернов

Новый конструктор должен опираться на уже существующие элементы страницы:

- базовые карточки и панели из `SurveysPage`;
- текущую палитру и радиусы из `surveys.css` и связанных общих стилей;
- существующий dropdown/select-паттерн, уже используемый в webapp;
- текущий шрифт и плотность интерфейса приложения.

Редизайн не должен выглядеть как отдельный продукт или новая визуальная система.

## Поведение пустых состояний

- если у выбранной аудитории нет активного опроса, в секции `Активный опрос` показывается компактное пустое состояние;
- если нет сохраненных шаблонов, секция `Сохраненные опросы` показывает короткое сообщение без лишнего текста;
- если вопросов нет, правая область показывает только карточки настроек опроса и кнопку `Добавить вопрос`.

## Критерии готовности дизайна

Дизайн считается реализованным корректно, если:

- во вкладке `Конструктор` появился отдельный сайдбар с переключателем `Клиенты / Сотрудники`;
- `Активный опрос` и `Сохраненные опросы` разделены на две явные секции;
- справа используется только одна вертикальная колонка карточек;
- блок `Запуск` вынесен в отдельную карточку;
- детальные настройки запуска открываются через `Настроить` в модальном окне;
- вопросы поддерживают типы `Шкала оценки`, `Один выбор`, `Множественный выбор`, `Комментарий`;
- шкала визуально показывает диапазон `1-10`;
- карточки компактные и совпадают по стилю с приложением;
- служебный текст на карточках не переносится;
- dropdown/select и другие контроли выглядят единообразно;
- экран остается читаемым на узких экранах.
