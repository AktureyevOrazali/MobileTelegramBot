## API-паритет: что есть в web API и отсутствует в mobile API

Отсутствуют в `mobile/lib/api/api_client.dart` методы, которые есть в `webapp/src/api/ApiClient.ts`:

1. `fetchOrganizationsWithoutContracts()`
2. `getBinsDetailed(query?)`
3. `getBinInfo(binValue)`
4. `deleteBin(binValue)`
5. `fetchDashboardSummary({ operatorId, startDate, endDate })` (в mobile есть только `operatorId`)
6. `updateProfile(..., email)` (в mobile не поддержан аргумент email)

## Что это блокирует в mobile прямо сейчас

1. Нельзя показать состояние договора БИН (`hasContract`) и детали (банк/адрес).
2. Нельзя реализовать экран/модалку "Все БИНы" как в web.
3. Нельзя показать список организаций без договора.
4. Нельзя удалить БИН из мобильной админки.
5. Нельзя строить дашборд по датам (preset/custom).
6. Нельзя добиться полной паритетности профиля (редактирование email).

## План внедрения в mobile (по этапам)

## Этап 1. API-паритет (обязательный фундамент)

Сделать в `mobile/lib/models/models.dart` и `mobile/lib/api/api_client.dart`:

1. Добавить модели:
- `OrganizationWithoutContract`
- `BinDetailed`

2. Добавить методы API:
- `fetchOrganizationsWithoutContracts()`
- `getBinsDetailed({String? query})`
- `getBinInfo(String bin)`
- `deleteBin(String bin)`

3. Расширить `fetchDashboardSummary`:
- добавить параметры `startDate`, `endDate`
- прокидывать в query: `start_date`, `end_date`

4. Расширить `updateProfile`:
- добавить optional `email`
- отправлять поле `email` при обновлении профиля.

Критерий готовности:
- все методы вызываются из mobile без ошибок 4xx/5xx на актуальном backend;
- модели корректно парсят ответы.

## Этап 2. Админка: БИНы и договоры (ключевой gap)

В `mobile/lib/screens/admin_user_management_view.dart`:

1. Добавить верхние карточки-метрики (как в web):
- Все БИНы
- Без договора
- С договором
- Регистрации

2. Добавить модалку "Все БИНы":
- поиск по БИН
- список с бейджем `договор / без договора`
- клик по БИН -> детали (`bank`, `address`, `hasContract`)
- удаление БИН (`deleteBin`) с подтверждением.

3. Добавить модалку "Организации без договора":
- список организаций (`customerBin`, при наличии адрес/банк)
- назначение выбранного БИНа оператору.

4. В блоке неразделенных БИНов вернуть карточку описания выбранного БИНа
(состояние договора, банк, адрес).

Критерий готовности:
- mobile повторяет web-сценарии по БИН/договорам без потери функционала.

## Этап 3. Дашборд: довести до web-паритета

В `mobile/lib/screens/dashboard_view.dart`:

5. Разделить экран на вкладки (overview/operators/sections/activity) или сделать сегментированный control, чтобы UX совпадал с web-логикой.

Критерий готовности:
- значения/фильтры на одинаковом наборе данных совпадают с web.

## Этап 5. Профиль: завершение паритета

Критерий готовности:
