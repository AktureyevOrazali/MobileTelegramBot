# Редизайн аналитики клиентских опросов

## Контекст

Во вкладке `Опросы клиентов` текущая аналитика построена вокруг выбора одного вопроса. Такой сценарий не соответствует целевой задаче:

- страница показывает только один вопрос за раз;
- ключевые клиентские метрики приходится искать вручную;
- визуально вкладка не совпадает со стилем аналитики сотрудников;
- структура страницы плохо масштабируется, если в опросе несколько типов вопросов.

В коде это выражено тем, что клиентская аналитика использует `QuestionAnalyticsWorkspace`, где весь экран зависит от `selectedQuestion`.

## Цель

Переделать вкладку `Опросы клиентов` в полноценный dashboard по всем клиентским вопросам сразу, без селектора вопроса, в визуальном стиле, близком к странице аналитики сотрудников.

## Не входит в задачу

- переделка вкладки `Оценка клиентов сотрудниками`;
- переделка вкладки `Сводная аналитика`;
- изменение API или серверных контрактов;
- добавление drill-down по отдельному вопросу.

## Принятое решение

Для клиентской аналитики вводится отдельная dashboard-модель вместо переиспользования `QuestionAnalyticsWorkspace`.

Причина:

- текущая оболочка жёстко завязана на один выбранный вопрос;
- новый экран должен агрегировать все вопросы сразу;
- отдельная модель уменьшает количество обходной логики и делает код понятнее.

## Целевая структура страницы

### Верхняя часть

Сохраняются:

- общий заголовок страницы;
- выбор периода;
- кнопка `Обновить`;
- текущие табы разделов.

### Первый ряд

Две крупные карточки:

1. `Общая картина`
   - число завершённых клиентских анкет;
   - средний балл по шкальным вопросам;
   - число клиентских вопросов в аналитике;
   - число всех клиентских ответов;
   - короткие поясняющие KPI в стиле существующих карточек.

2. `Динамика и структура ответов`
   - `donut chart` по тональности шкальных ответов;
   - `line chart` по количеству завершённых клиентских анкет по месяцам.

### Второй ряд

Три компактные карточки в том же визуальном паттерне, что и на странице сотрудников:

1. `Топ ответов по вопросам`
   - наиболее частые варианты по choice-вопросам;
   - показываются как горизонтальные бары.

2. `Популярные темы`
   - агрегированные клиентские темы;
   - показываются как горизонтальные бары.

3. `Запросы и пожелания`
   - агрегированные клиентские пожелания и запросы;
   - показываются как горизонтальные бары.

### Третий ряд

Две табличные карточки:

1. `Все вопросы`
   - полный список клиентских вопросов в выбранном периоде;
   - сравнительная таблица без выбора одного вопроса.

2. `Последние ответы`
   - последние клиентские анкеты или последние клиентские ответы;
   - нужен живой операционный срез, а не только агрегаты.

## Логика данных

### Donut chart

`Donut chart` строится по всем шкальным клиентским ответам сразу.

Категории:

- отрицательные: оценки `1-2`;
- нейтральные: оценка `3`;
- положительные: оценки `4-5`.

В центре donut показывается:

- общий средний балл по всем шкальным клиентским вопросам;
- подпись, что это средний балл.

Если шкальных ответов нет, donut не рисуется и вместо него показывается пустое состояние.

### Line chart активности

`Line chart` строится по количеству завершённых клиентских анкет по месяцам в выбранном диапазоне.

Требования:

- ось X: месяцы;
- ось Y: количество анкет;
- линия одна, без переключателей;
- если периодов недостаточно, показывается пустое состояние.

### Карточка общей сводки

Сводная карточка использует все клиентские данные сразу и не зависит от отдельного вопроса.

Базовые метрики:

- завершённые анкеты;
- средний балл;
- всего ответов;
- всего вопросов.

Дополнительные строки внутри карточки:

- доля положительных ответов;
- доля нейтральных ответов;
- доля отрицательных ответов;
- охват вопросов или число вопросов со статистикой.

### Карточка `Топ ответов по вопросам`

Источники данных:

- только choice-вопросы, где есть варианты ответов.

Правила:

- объединяются ответы по всем клиентским вопросам;
- каждая строка показывает вариант ответа и количество;
- список ограничивается верхними позициями, чтобы карточка не расползалась.

### Карточка `Популярные темы`

Используются уже доступные агрегаты клиентских тем из существующей аналитики.

Правила:

- сортировка по убыванию;
- не более 4-6 позиций;
- визуализация в виде компактных горизонтальных баров.

### Карточка `Запросы и пожелания`

Используются уже доступные агрегаты по клиентским запросам и пожеланиям.

Правила:

- сортировка по убыванию;
- не более 4-6 позиций;
- визуализация в виде компактных горизонтальных баров.

### Таблица `Все вопросы`

Каждая строка представляет отдельный клиентский вопрос.

Столбцы:

- вопрос;
- тип вопроса;
- число ответов;
- средний балл для шкальных вопросов;
- краткий итог.

Под кратким итогом понимается:

- для шкалы: доля положительных ответов или тональный итог;
- для choice-вопросов: самый частый вариант;
- для текстовых вопросов: число текстовых ответов.

### Таблица `Последние ответы`

Цель таблицы:

- показать последние клиентские события в понятном операционном виде;
- визуально приблизить страницу к аналитике сотрудников, где есть блок последних записей.

Столбцы определяются исходя из уже доступных полей клиентской аналитики, но ориентир такой:

- клиент или сущность;
- ответ или итог;
- контекст;
- дата.

Если доступно только ограниченное количество полей, используется минимальный рабочий набор без изменения API.

## Изменения в компонентной структуре

### Что убирается

- селектор вопроса во вкладке `Опросы клиентов`;
- зависимость клиентского экрана от `selectedQuestion`.

### Что добавляется

- отдельный компонент клиентского dashboard;
- отдельный builder/model для клиентской аналитики по всем вопросам;
- отдельные chart builders для donut и activity line;
- таблица со всеми вопросами;
- таблица последних ответов.

### Что переиспользуется

- общая обвязка страницы;
- карточки `Card`;
- `EChartsWrapper`;
- существующие стили карточек и таблиц;
- визуальные паттерны страницы сотрудников;
- форматтеры дат, процентов и чисел, уже лежащие в `SurveysPage.tsx`.

## Изменения в стилях

Страница должна визуально приблизиться к аналитике сотрудников и к первому референсу.

Требования:

- сохранить существующую визуальную систему `surveys-page--app-sidebar`;
- использовать те же радиусы, тени, таблицы и плотность карточек;
- усилить первый ряд, чтобы он выглядел как главный аналитический блок;
- не оставлять пустых зон, характерных для текущего экрана с выбором одного вопроса;
- обеспечить адекватное поведение на tablet/mobile через существующие responsive breakpoints.

## Поведение пустых состояний

Если данных по клиентским опросам нет:

- страница не ломается;
- показываются пустые состояния в карточках и таблицах;
- отсутствие данных не приводит к скрытию всей секции.

Если есть только часть данных:

- доступные карточки строятся;
- недоступные графики и таблицы показывают локальный `EmptyState`.

## Технический план реализации

1. Выделить отдельный клиентский dashboard вместо `QuestionAnalyticsWorkspace`.
2. Собрать агрегаты по всем клиентским вопросам из уже полученной `SurveyAnalytics`.
3. Построить новый screen model для вкладки клиентов.
4. Добавить donut chart по шкальным ответам.
5. Добавить line chart активности по завершённым анкетам.
6. Пересобрать средний ряд из трёх компактных карточек с барами.
7. Добавить таблицу `Все вопросы`.
8. Добавить таблицу `Последние ответы`.
9. Обновить CSS так, чтобы клиентская вкладка визуально совпадала с аналитикой сотрудников и референсом.

## Проверка результата

После реализации нужно проверить:

- во вкладке `Опросы клиентов` больше нет селектора вопроса;
- страница показывает все вопросы сразу;
- donut использует категории `1-2`, `3`, `4-5`;
- в центре donut показывается общий средний балл;
- line chart показывает количество анкет по периодам;
- карточки визуально согласованы со страницей сотрудников;
- таблица `Все вопросы` содержит все клиентские вопросы;
- таблица последних ответов показывает живые записи;
- пустые состояния не ломают сетку;
- вёрстка сохраняет читаемость на узких экранах.
